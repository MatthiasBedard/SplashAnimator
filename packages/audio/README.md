# @splash/audio

`src/pcm.ts` supplies synchronous offline PCM timeline mixing. `audioSampleRange` rounds absolute frame boundaries; `mixTimelinePcm` accepts normalized mono/stereo Float32 clips at the output sample rate, root start frames, source-sample offsets and signed gain. Ranges are end-exclusive. It validates all sources, fills gaps with silence, sums overlaps before hard-clipping and reports pre-clip peak and clipped channel-sample count. Inputs are not modified and returned channels own their storage.

Output storage is limited to 128 MiB by default. A separate 50-million work budget covers source validation plus sample/clip visits; at most 10000 clips are admitted. Lower caller budgets can reject earlier. This simple synchronous algorithm is not a real-time mixer or a memory/latency qualification. Source buffers must remain stable during the call; caller-owned source memory is outside the output budget.

Five unit cases and a Chromium OfflineAudioContext sample comparison verify the initial core. `pcm-async.ts` now provides disposable worker hosting with copied input buffers, transferred output, bounded envelope/sample validation, cancellation and a 10-second default deadline (maximum 60 seconds). It counts unique source backing buffers against a 128 MiB clone budget and rejects shared buffers. Three lifecycle units and three real-browser snapshot/timeout/cancel/retry workflows passed using test bundles. Synchronous input copying and output validation cannot be interrupted by worker deadlines. No production worker asset qualification, resampling/channel conversion, document audio tracks, live playback or editor export integration is claimed.

`wav.ts` admits PCM16 mono/stereo RIFF/WAVE assets with strict chunk, alignment and rate checks before allocating output. Limits are 64 MiB input view, 128 MiB planar output and 10000 chunks. Other encodings/extensions reject. The signed conversion uses a uniform 32768 divisor; positive full scale is 32767/32768. Five units and two independent Chromium decoding comparisons passed; Chromium positive normalization differs by at most one PCM16 step on the fixtures. `wav-async.ts` adds cancellable disposable worker decoding with a 10-second default/60-second maximum deadline. It copies only admitted input-view bytes into a transferred snapshot, leaves caller buffers intact, and validates transferred PCM output. Three lifecycle units and four real-browser snapshot/timeout/cancel/invalid-file/retry workflows passed using test bundles. Snapshot copying and output scans remain synchronous; production assets and editor integration are still pending.

Format reference: [Microsoft WAVEFORMATEX](https://learn.microsoft.com/en-us/windows/win32/api/mmreg/ns-mmreg-waveformatex).

Browser Control > Preview audio now uses the real lazy decode/mix worker assets for a transient local WAV preview. Prepare is silent and bounded by a shared 10-second deadline; Play/Stop controls a dedicated AudioContext independent of the stage. Start frame/gain affect only the temporary mix, with output statistics and clipping reports. Replacement/close cancels work and disposes playback; reopening starts empty. Five production workflows cover lifecycle, errors, retries, timing samples and unchanged recovery. This does not add document audio tracks, synchronized stage playback or audio exports, and does not qualify audible hardware/native behavior. Earlier test-bundle-only notes above describe their original checkpoints.

`import.ts` prepares a decoded, metadata-validated WAV payload and detached candidate project with optional explicit clip. It never writes files or publishes live state. Callers must persist the immutable payload, verify the returned base signature and then publish through history. Serial budgets/deadlines and original-value validation apply; UI/binary-store integration remains pending.

`persistAudioImport` accepts only unchanged, session-admitted preparations and invokes exclusive binary storage once. It checks the current validated project signature before and after writing and returns a detached candidate for final guarded publication. Errors after storage invocation expose `assetMayExist` and the path: they do not promise rollback. Callers still need a final synchronous signature check, history publication and manifest conflict handling. Browser transport/UI integration remains pending.

`wav-encode.ts` encodes normalized mono/stereo Float32 PCM into bounded PCM16 RIFF/WAVE output. It validates original samples before allocation, rounds with a uniform 32768 scale and saturates positive full scale to 32767. Output includes a 44-byte header and caps at 64 MiB. No dithering/resampling, worker or editor export integration is included yet.
