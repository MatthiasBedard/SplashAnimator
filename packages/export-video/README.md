# @splash/export-video

Browser File-menu GIF export supports full/selected ranges at document size, optional transparency with white matte edges, cancellation and opt-in infinite looping. One-shot playback remains the default. Detached exact-frame replay preserves earlier nested clock history and keeps document scripts inert.

`src/gif.ts` offers an incremental `createIndexedGifEncoder` with declared frame count, immediate frame consumption and complete-output-only publication. The complete-buffer API uses bounded output storage; dictionary compression grows and trims buffers, which can temporarily coexist. `createIndexedGifChunkEncoder` instead sends owned chunks to a synchronous sink, avoiding that full allocation. Those chunks are provisional until finish; callers must discard or abort destinations on failure. A separate chunk worker now requires exact acknowledgment of each chunk and bounds pending per-request output to 16 MiB by default. `gif-chunk-async.ts` acknowledges chunks after asynchronous sink writes, aborts failed/cancelled destinations and returns a final receipt without publishing. Sinks must discard provisional bytes and prevent late writes after abort. `gif-destination.ts` adapts locked writable streams with receipt-checked commit and abort cleanup; real Chromium origin-private file commit/rollback is verified. Generic streams cannot guarantee rollback. Final close is noncancellable once begun. Production Save GIF to file commands now use this adapter and the chunk host; native picker/user-filesystem qualification remains pending. The all-at-once wrapper uses the same encoder. It encodes indexed full-screen GIF frames with a shared RGB palette, centisecond delays and background disposal. Literal LZW remains the default. File > Compress GIF with LZW dictionary opts into 9-to-12-bit dictionary encoding for full/selected downloads and saves. The choice snapshots before async work; completion status reports the encoding. Dictionary state is fixed-size, output bytes are bounded, and noisy inputs may grow rather than shrink. Infinite looping uses a Netscape application extension; its bytes count toward the output budget.

`gif-rgba.ts` exposes incremental palette analysis that retains a bounded color table rather than raster frames, with detached settings and exact-color replay guards. It retains exact shared colors when they fit, otherwise reports fixed 6x6x6 cube quantization. The preparation/analyzer APIs accept optional `dither: "ordered"` for a coordinate-anchored 4x4 pattern on reduced palettes only; default `"none"` and exact palettes remain unchanged. The option uses constant storage. File > Dither reduced GIF colors enables it for download and save-to-file; it is off by default and exact palettes remain unaffected. Completion status identifies ordered dithering only when reduction occurred. Zero alpha can remain transparent; partial alpha composites against an explicit matte. Rounded absolute frame boundaries distribute delays and retain selected-range phase; rates above 100 fps reject.

`gif-async.ts` retains the all-at-once worker API for callers that need it. Inputs clone by default; explicit `transferFrames` consumes full owned buffers, including on later failure/cancellation.

Browser export uses `gif-stream-async.ts` and the ordered two-pass worker protocol with one request in flight, exact acknowledgment validation, cancellation and a shared 60-second export deadline. Two fresh detached renderers replay prior frames for nested clocks, then transfer selected frames one at a time: palette analysis first, encoding second. SHA-256 digests compare selected RGBA frames across passes before encoding (4 MiB digest budget); mismatch cancels publication. Web Crypto is required and digest waits observe cancellation/deadlines, although underlying digest jobs cannot be cancelled. Production assets and pixel/failure/cancel workflows are verified. The download worker retains one indexed buffer and the complete output; the save-to-file path uses acknowledged bounded chunks and receipt-checked final close instead. The editor no longer retains all RGBA frames. The existing 128 MiB aggregate RGBA work limit stays pending qualification. Two passes increase rendering work; synchronous compilation/readback/transfer, asset consistency, maximum/native/resource/fidelity remain open. This does not complete M6's original FFmpeg video/GIF requirement.

Format reference: [GIF89a specification](https://www.w3.org/Graphics/GIF/spec-gif89a.txt). Graphics Interchange Format and GIF are CompuServe properties.

`src/webm-av.ts` adds a separate `createAvWebmWriter(video, audio, maxBytes?)` for already encoded VP8 and Opus packets. Existing silent `createWebmWriter` and editor exports keep their exact behavior/bytes. This API performs no encoding or payload inspection. Opus is explicitly limited to mapping-family-0 mono/stereo, 48 kHz input/output and zero gain. Audio settings declare `channels`, `preSkip` (48 kHz samples), `packetCount`, total decoded `sampleCount` including priming/padding, and final `endTrim` samples. All values snapshot once. Packet durations supplied to `appendAudio(packet, durationSamples)` must be multiples of 120 samples, from 120 through 5760, and total the declared sample count. The caller must supply actual codec durations and keyframe flags. Feasibility checks reserve enough samples for every remaining packet and a nonempty final packet after trimming.

`appendVideo(packet, keyFrame)` uses the declared rational frame rate. Video starts at zero; audio starts at decoded sample zero before pre-skip. Submit packets in increasing raw timestamp order across both tracks (ties may use either order). The writer rejects submissions that would skip the other track's next boundary. CodecDelay subtracts pre-skip from audio playback timestamps; positive final DiscardPadding removes end trim. The container includes OpusHead, 80 ms SeekPreRoll, per-packet audio BlockDuration, nominal video DefaultDuration, rounded rational microsecond clusters, video-keyframe cues and an exact SeekHead. Packets with the same raw timestamp share a cluster, retaining both track blocks and correct video cue block numbers even when audio is submitted first. Segment duration is the longer of the video boundary and audible audio end. There are no gaps or arbitrary caller timestamps in this first API.

Only `finish()` publishes complete owned bytes after exact counts. Invalid/incomplete calls leave retained valid state available for retry; `abort()` clears retained data and closes the writer. Packets copy before retention, including subarrays; empty, detached and shared buffers reject. The default/maximum output budget remains 128 MiB with conservative metadata reservations, and video retains the 10001-frame limit. Assembly is synchronous and retains owned packet blocks plus a complete final output; the byte cap does not certify peak memory or maximum-project acceptance. No browser Opus encoder, codec decode/playback qualification, audio export command, streaming destination, cancellation host, native/FFmpeg delivery or original M6 completion is provided by this packet muxer.

Format references: [WebM container guidance](https://www.webmproject.org/docs/container/), [Matroska Opus mapping](https://www.matroska.org/technical/codec_specs.html#a_opus), [Matroska element definitions](https://www.matroska.org/technical/elements.html), [Matroska versioning](https://www.matroska.org/technical/notes.html) and [RFC 7845 identification headers](https://www.rfc-editor.org/rfc/rfc7845.html#section-5.1). Synthetic packet tests establish container structure, not codec validity.

`src/opus.ts` now provides `encodeOpus(channels, bitrate, options?)` for detached normalized mono/stereo Float32 PCM at exactly 48 kHz. It captures native constructors/settings before asynchronous capability probing, validates intrinsic channel dimensions and all samples, and snapshots planar PCM within the existing 128 MiB work limit. One complete AudioData input and one final flush avoid resetting priming at intermediate flush boundaries. Requested raw Opus uses 20 ms packets; capability/configuration/OpusHead must explicitly match 48 kHz, zero gain and family 0. Native pre-skip comes from the identification header; it is never guessed. Actual TOC framing/timing, key type, absolute timestamps, duration, output count and byte reservations validate before complete owned packets/track settings publish. Final trim is derived from decoded total minus pre-skip and original sample count, with less than one final packet of padding. RFC 6716 framing checks do not entropy-decode or certify arbitrary codec payloads.

Cancellation and the shared per-job deadline cover capability probing, validation/copying checks and final native flush; late callbacks cannot revive rejected work. Errors/reentry/count/timing/metadata/budget failures clear retained packets and close native resources/timers. Native encoding and synchronous full-input scans/copies may continue until the platform returns control. Original PCM, detached planar input, AudioData/native codec storage and encoded output can coexist. This first host deliberately supports only 48 kHz normalized input and strict 20 ms native output; it performs no resampling, gain adjustment or editor integration. Real Chromium mono/stereo tests mux encoded packets with VP8 and independently decode WebM audio to the exact original sample count with channel-content correlation, including non-packet-aligned trim. These fixtures do not certify physical audio devices, arbitrary codec platforms, video/audio playback synchronization, maximum resources or original M6 delivery gates. Native Ogg mode was unsupported in the tested Chromium; raw mode supplied the required OpusHead. Missing/incompatible header or capability rejects explicitly.

Native API references: [WebCodecs](https://www.w3.org/TR/webcodecs/) and [Opus WebCodecs registration](https://www.w3.org/TR/webcodecs-opus-codec-registration/); packet framing references [RFC 6716 section 3](https://www.rfc-editor.org/rfc/rfc6716.html#section-3).

`src/vp8-packets.ts` offers `openVp8PacketEncoder(settings, options?)` separately from existing `openVp8Encoder`. It uses captured native constructors/settings and one detached, opaque RGBA VideoFrame per awaited append/flush. Primitive numeric validation precedes arithmetic; intrinsic byte lengths/buffers and ordinary owned copies avoid caller getters/species. Invalid input pixels remain retryable, while any native output failure is terminal. Exact counts, rational timestamps/durations, scheduled keyframes (additional native keyframes allowed), optional matching decoder configuration and byte reservations validate before retaining packets. Native packet fields read once; callback reentry, omission/extras, malformed timing/type/configuration/copy, cancellation/deadline and native construction/configuration errors clear retained output and native/timer resources. Nullable native chunk durations use the original submitted frame's rational duration; any supplied duration must match it.

Only complete `finish()` returns owned packet objects (`bytes`, `keyFrame`, `timestampUs`, `durationUs`) plus dimensions/rate/count/key/delta/payload-byte totals. No container is produced, parsed or encoded again. The 128 MiB RGBA work/output ceilings, 10001-frame WebM-compatible range and conservative framing/remaining-packet reservations stay explicit. The caller must still admit the combined audio/video container budget. Source RGBA, frame/native storage and retained encoded packets coexist; scans/copies/packing/native cleanup remain resource limits. Existing IVF/WebM defaults and bytes are untouched. Real Chromium fixtures decode new-host key/delta packets to exact rational frame times/red-blue pixels, then mux them with native Opus and extract exact-length/channel-content audio. They do not establish audiovisual device playback synchronization or original M6/native/resource/fidelity/FFmpeg completion. No editor command changes.

`src/av-webm.ts` adds `encodeAvWebm(videoSettings, pcmChannels, audioBitrate, readFrame, options?)`. It snapshots video settings and all native codec dependencies before asynchronous work; Opus owns its PCM snapshot before capability probing. Encoded audio completes first, then a serial frame source supplies RGBA for the captured video count. Synchronous frame results snapshot before queued caller mutation; asynchronous sources must keep delivered frames stable until consumption and honor the provided signal where possible. One absolute deadline spans audio, source waits, video and muxing. No stage receives a fresh time allowance. Metadata plus at least one byte per future video packet are reserved from the audio budget, then retained audio bytes/metadata are removed from the video budget. A final combined admission precedes ordered muxing and complete-output-only publication. Returned bytes include actual audio pre-skip/end trim/count, original PCM length and video key/delta totals.

Errors/cancellation/deadline at any stage dispose active codec work, ignore late sources, clear private packet receipts and publish no partial output. Source promises that ignore their signal can outlive the rejected job; callers retain source cleanup and project/asset consistency responsibility. Equal-time cluster coalescing fixes the observed Chromium delta-frame seek failure when the initial audio/video blocks were split into separate clusters. Codec bytes, rational timing, the microsecond scale and all silent writer bytes remain unchanged. Native mono/stereo fixtures now verify the complete wrapper's WebM duration, forward/backward red/blue video seeks (including between-frame targets) and independently extracted exact-length audio/channel content. This remains an API prerequisite for detached project/audio capture; it does not load project WAV assets, execute scripts, expose editor export commands, guarantee audiovisual device synchronization or complete original M6/native/resource/FFmpeg/fidelity gates. Whole PCM/native/packet/container copies can coexist, and synchronous muxing remains an uninterruptible resource cost between deadline checks.

New browser fixtures cover full/selected ranges, original nested-clock colors, root/child remembered motion, WAV resampling/channel content, live source/metadata/cancel/timeout rejection, late assets/fresh retries, worker/native/iframe cleanup and unchanged recovery. `prepareAvWebmChunks(video, audio, packets, maxBytes?)` is a separate complete-sequence preparation API. Each request is `{kind: 'video', bytes, keyFrame}` or `{kind: 'audio', bytes, durationSamples}`, ordered by the same implicit raw timestamps as the complete writer (ties may use either order). Original configuration/count/fields and encoded packet bytes detach during synchronous preparation. All counts/timing/order/byte budgets validate before a returned facade can expose output. Missing, malformed or late invalid requests reject the entire preparation. Opaque payloads are not codec-certified.

The frozen result includes the complete byte/frame/audio/duration/rate receipt, `next(): Uint8Array | undefined` and idempotent `dispose()`. Pulls return independent transferable chunks of at most 65536 bytes; exhaustion returns undefined repeatedly, and pulls after dispose throw. Consumed blocks release as output advances. A segmented EBML plan preserves exact complete-writer bytes, segment sizes, SeekHead/cues and audio-first equal-time video block numbers without joining clusters or a whole container. Consumers must await sink writes and verify the full byte receipt before committing any provisional destination. This synchronous API has no sink/worker/cancellation host and never closes a destination. Callers still retain their original packets, preparation retains owned blocks/metadata, and consumers can retain every chunk; this does not certify peak memory or streaming codec performance. Existing editor AV commands still use complete output. Original native/filesystem/resource/FFmpeg/fidelity gates remain open.
